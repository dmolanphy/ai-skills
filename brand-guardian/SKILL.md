# Brand Guardian

Build brand systems that hold together, and defend them once they exist. Every deliverable
either compounds the brand or erodes it. **Strategy before artifacts:** establish the
foundation before designing logos, picking palettes, or writing taglines.

## Route first

- **Building a brand or identity** → Foundation, then Visual identity, then Voice.
- **Checking work against an existing brand** → Audits.
- **Refresh or extension question** → Evolution calls.

If an existing brand's guidelines exist, read them before anything else.

## Brand foundation framework

Work in order; each step depends on the one before:

- **Purpose** — why the brand exists beyond profit. One sentence, no poetry.
- **Vision** — the aspirational future state.
- **Mission** — what it does, for whom, concretely.
- **Values** — 3 max, each with a behavior ("we do X, which looks like Y"). Values without behaviors are wall art.
- **Personality** — 3 human traits, each with how it shows in design and language.
- **Promise** — the one thing customers can always expect.

Then positioning: primary + secondary audience, differentiation (what only this brand can
claim), 3–5 pillars, and a one-sentence positioning statement. Pressure-test it: if a
competitor could say the same sentence, it isn't positioning.

Present foundation work as 2–3 distinct strategic directions, each with a named POV, not one
merged compromise. **Checkpoint:** get the user's pick before starting visual identity or voice.

## Visual identity system

Specify at minimum: logo system (primary, horizontal, stacked, icon; clear space; minimum
sizes; do's and don'ts), color system (primary / secondary / neutral palettes with hex values,
WCAG-compliant combinations flagged), typography (display + body, hierarchy, web fallbacks),
and any pattern/illustration language. For token-level implementation (variables, Figma
foundations), hand off to `ds-foundations`: this skill defines the identity, that one builds it.

## Voice and messaging architecture

- **Voice:** 3 traits, each with usage context and an example line.
- **Tone map:** how voice flexes by context (sales page vs. error message vs. crisis).
- **Messaging:** tagline, value proposition, 3 key messages ranked by audience priority.
- **Writing guidelines:** preferred vocabulary, banned phrases, inclusive-language rules.

Align with the `writing-style` skill: plainspoken, no corporate jargon, confident but not performative.

## Audits

1. Check against the foundation first (does it express values and personality?), then
   against visual/verbal guidelines. Flag which level each violation lives at: strategy
   misses matter more than spacing misses.
2. Distinguish drift (repeated small deviations that weaken the system) from evolution
   (deliberate flexes that extend it). Name which one you see and why.
3. Deliver: what's working / what's eroding / what to fix first, ranked by damage, not ease.

## Evolution calls

Consistency is the default; change needs a reason rooted in audience or market shift, not
boredom. State the tension, give the recommendation, and show what stays fixed no matter what.
